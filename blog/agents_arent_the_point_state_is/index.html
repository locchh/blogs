Agents Aren't the Point. State Is.

I keep restating the same idea on this blog, one layer deeper each time. The model is rented. The harness is the job. Now I think there’s a layer under both: the state of the work.

Here’s the test. A piece of work — a coding task, a support ticket, a research thread — should be able to pass through a human alone, a human and an AI working together, or an AI alone, and keep moving smoothly from start to finish. Not perfectly, but without breaking. If swapping the actor breaks the work, the problem isn’t the actor. It’s that you never actually defined the state — you were carrying it in someone’s head, or in one tool’s session, instead of somewhere any actor could pick it up.

Git already proved this, quietly, for twenty years. A commit doesn’t care who made it. A branch doesn’t care if the last five commits were typed by a person or generated by an agent — it only cares whether the diff applies and the tests pass. That’s the whole trick: state that’s actor-agnostic by construction.

LangGraph built this on purpose

LangGraph makes the state explicit: one shared object, flowing through nodes, and a checkpointer that saves it after every step. Crash, and you resume from the last checkpoint instead of starting over.

This is one of computing’s oldest moves, not a framework feature. Mainframe batch jobs in the 1960s wrote checkpoints to tape because the hardware failed mid-run — any machine, or any operator, could pick the job up from the last one. Databases hardened the same move into the write-ahead log: crash the server, start a new one, replay the log, and nobody can tell the difference. LangGraph’s checkpointer is that move, sixty years later, applied to a graph of model calls.

The sharp part is interrupt(). A node calls it, execution pauses, the full state is checkpointed, and control returns to whoever’s driving. To continue, someone sends Command(resume=value) — and the graph doesn’t ask who sent it. A human typing into a UI and a model finishing a tool call both look exactly the same to the graph: a resume value injected into shared state. LangGraph never had to special-case “human’s turn” versus “AI’s turn,” because it never modeled turns at all. It modeled state transitions. Whoever supplies the next one is not the graph’s problem.

One honest caveat, since I don’t want to oversell it: checkpointing state isn’t the same as durable execution. LangGraph saves the state faithfully. It doesn’t supervise the process running it — no watchdog, no heartbeat. If the runtime dies mid-step, the state survives; nothing notices to resume it. State outliving its actor is only half of durable — you still need something watching to hand it to the next actor.

Claude Code and Codex bet the other way

Tools like Claude Code and Codex aren’t state graphs. They’re closer to one general-purpose agent trying to be the actor for almost anything — a session, a context window, a tool loop, compacted and carried forward as one continuous run. Less “define the process up front,” more “give the agent enough rope and let it figure out the shape of the task itself.” Fair bet: most real work doesn’t arrive as a clean, pre-known graph of steps. You often don’t know the shape of the task until you’re in it.

But watch what actually makes these tools swappable. You can drop Claude Code mid-task, pick up Codex, and keep going — not because the agent transferred, but because the real state was never inside the agent’s session at all. It was sitting in the repo the whole time: the files, the git history, the todo list, a CLAUDE.md. The session is disposable. It always was. These tools look actor-first, but the reason they survive an actor swap is the exact same reason LangGraph does — durable state, sitting outside whichever actor currently holds the pen.

This isn’t two products, it’s a category. OpenCode and Kimi Code make the same bet — open, provider-agnostic, single-agent terminal loops you drive from a session, same shape as Claude Code (OpenCode even has the same switchable build/plan modes). MiMo-Code, Xiaomi’s entry, goes one step further and proves my point for me: it externalizes its state on purpose, as files — a project MEMORY.md, a checkpoint.md, per-task progress.md logs — instead of leaving it implicit in the session. That’s this whole essay, shipped as a feature. hermes-agent and OpenClaw take the same actor-first bet and stretch it past coding entirely — a gateway routing you to one general-purpose agent across Telegram, Slack, email, wherever you are. Same philosophy, wider net.

None of this is new. It has a name.

“State” sounds like a design choice. It’s actually seventy years of automata theory, and the history explains exactly why LangGraph needed reducers.

The finite state machine started life as a neuron, not a computer: McCulloch and Pitts (1943) drew it to model how nerve cells fire. Kleene (written 1951, published 1956) turned that into the modern finite state machine.

Worth saying out loud, because the name hides it: an FSM is a graph. The states are the nodes. The transitions are the edges, each one labeled with the event that triggers it. That’s how it’s drawn in Sipser’s automata lectures and in every textbook since. At any moment the work sits on exactly one node, and the edges out of it are the only legal next moves. So “what’s the state?” is really just “which node are we standing on?”

Mealy and Moore (1955–56) added the piece that matters for agents: moving along an edge doesn’t only relabel you, the machine also emits something as it goes. That’s the shape of a LangGraph node. Arriving isn’t “we’re at step 3 now,” it’s “we’re at step 3, and step 3’s model call just ran.”

Notice the loop, because I didn’t expect it. Eighty years later, we take networks of model neurons and wrap them back inside state machines, so the work survives the actor. The two ideas have traded places.

But that graph has a flaw built into its definition: you stand on exactly one node at a time. Carl Adam Petri’s dissertation (submitted 1961, defended 1962) exists because he thought that assumption was wrong for anything real — actual processes are asynchronous, and more than one thing is true at once. His fix was to stop tracking one position. A Petri net has places that hold tokens, and a transition fires wherever enough tokens have gathered. Tokens can sit in several places at once, so the graph holds multiple truths instead of one label. Workflow researchers built directly on this to formalize real business processes, because that’s what real work looks like — parallel, not sequential.

LangGraph’s reducers are the same fix, renamed. The moment two branches — a human and an agent, or two subagents — write to shared state at once, “we’re on one node” stops being true, and something has to decide how the writes merge. Not a LangGraph invention. Petri’s tokens, sixty years later, running on a Google Pregel-derived engine. A state model that can only hold one truth at a time breaks the first moment work happens in parallel — which, for anything with more than one actor, is immediately.

AI itself already ran this experiment, fifty years ago. Hearsay-II, a 1970s speech-understanding system, was built as a blackboard: a dozen independent specialist programs, none of which ever called another, cooperating only by reading and writing one shared board. The specialists were swappable by design, because the blackboard was the system. Long before anyone said “multi-agent,” the answer to coordinating actors was already: don’t. Let them meet in the state.

The ladder just grew a fifth rung

Look at what we’ve called this job over three years. Prompt engineering — write better instructions. Context engineering — the instructions were never the problem, what’s in the window is. Harness engineering — the window isn’t the problem either, it’s the tools and checks around the model. Loop engineering — one pass isn’t enough, let it run again. And now, this July, graph engineering.

LangChain named it directly after three years of building LangGraph: nodes do the work, edges decide what’s allowed next. A node can be plain code, one model call, a tool call, or a whole agent running its own loop. And the line they borrow from David Khourshid ends the fight before it starts — a loop is just a directed, cyclic graph. Loops were never the rival of graphs. A loop is the smallest graph there is. They make the same point from the other side: real agent graphs are almost never acyclic, because retrying, revising, and waiting on a human are the normal case, not the exception. So rung five doesn’t replace rung four, it contains it, the same way context contains the prompt and the harness contains the context. Each rung wraps the last one.

They say something else almost in passing, and it’s the part I’d underline. “Graph engineering isn’t a new idea,” they write. “It’s the latest name for a well established approach to building reliable agents” — the same idea behind loop engineering and harness engineering, “putting model reasoning in the right places, with the right context, at each step.” So the people who shipped the newest name are the ones telling you it isn’t a new one. They’re right. I’d just say the shared idea more literally. It isn’t only about where the reasoning goes. It’s one move, repeated: each rung takes something that was living inside the actor and puts it somewhere outside.

RungWhat moves out of the actor
Prompt engineeringthe instructions — out of your head
Context engineeringthe knowledge — out of the weights
Harness engineeringthe tools and checks — out of the model
Loop engineeringthe revision — out of a single pass
Graph engineeringthe state — out of the session

We aren’t getting smarter about agents. We’re moving more of the work out of them. And the last thing still stuck inside was the state — which is why this rung is the one that matters, and why I don’t expect the next name to be a new idea either. The session forgets. The state doesn’t.

One brake, and LangChain aims it at their own tool. Some work has real structure worth writing down — a support agent sorts the ticket before it answers, a coding agent reads the repo before it proposes a change. Some work doesn’t: “Some tasks are more agentic by nature, and forcing them into deterministic paths is the wrong move.” That’s them, about their own product. They built their early deep research on predefined LangGraph workflows, then moved it back to an open agent loop, because research doesn’t arrive with its steps known.

Which is the honest limit of this whole essay. The point was never “draw a graph.” It’s put the state where the next actor can reach it — and a loop with a state file already does that. My CLAUDE.md is a graph with one node in it, and it still does the job.

Lesson: design for state that outlives its actor. Whoever’s turn it is — human, AI, or both — the only job is to leave the state better-formed than you found it, and hand it off clean.
